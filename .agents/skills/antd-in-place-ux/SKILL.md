# Ant Design 页面交互设计

用于 antd 页面开发、改版或 UX 审查。核心是让用户在当前工作上下文中看见信息、执行操作并理解结果；是否留在当前页取决于任务复杂度，不把“少跳转”当成绝对规则。

## 本项目适配

`intelligent-hopper` 是 Vue 3 + Ant Design Vue 4.x 的独立 HTML 原型项目。落地时使用项目现有的 Vue 组件、资源和页面结构；既有 `enterprise-ui-optimization` Skill 对业务字段、密度和布局的项目约束继续适用。此 Skill 聚焦交互决策，不要求引入 React 版 antd。

## 工作方式

1. 先确认用户目标、当前页面的主要对象与任务链，观察现有信息层级和实际交互；尊重项目已有组件、版本、主题和业务约束。
2. 找出导致上下文丢失的跳转、刷新、重复确认和隐藏操作。逐项判断能否用页内编辑、详情或少量输入覆盖层、列表嵌入区、页签、虚拟页面、渐进展示或配置程序完成；复杂流程可保留独立页面，也可在合适的弹窗内用步骤条管理。
3. 为每个操作明确入口、触发、进行中、成功、失败、取消或撤销状态。重要操作保持可见；次要操作可在悬停时出现，但键盘、触屏也必须能发现和操作。
4. 删除等操作按后果选择策略：可可靠撤销时优先及时反馈与撤销；不可撤销或高代价操作使用贴近操作位置的确认。不要把示例中的“1 分钟”误写成通用超时要求。
5. 用现有 antd 组件和项目模式实现，必要时再定制。完成后在真实页面检查任务路径、信息可见性、焦点、键盘操作、窄屏表现、加载与错误反馈。

按场景读取 [交互决策参考](references/decisions.md)：它列出原页各章节与示例对应的判断点和官方出处。若任务涉及新增或调整动画，同时使用 `$antd-motion`。

输出建议具体到页面位置与交互状态，并说明改动对用户任务的作用；不要只给“更简洁”“更符合规范”之类的抽象结论。
