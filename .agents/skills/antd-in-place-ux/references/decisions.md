# 交互决策参考

这是从 Ant Design 官方规范提炼的工作判断，不是组件 API 或固定模板。以当前项目的 antd 版本、组件文档和业务规则为准。

| 场景 | 优先判断 | 实现时核对 |
| --- | --- | --- |
| 列表查看详情 | 详情是否可在原列表上下文中完成？少量信息可用点击触发的覆盖层；相关信息较多可用行内展开。 | 返回列表时保留筛选、排序、分页、滚动位置；覆盖层能关闭，焦点有去处。悬停详情按官方示例约 0.5 秒后触发、移出即关闭，但关键内容要有点击入口。 |
| 输入覆盖层 | 是否只需编辑少量字段且当前对象必须保持可见？ | 官方示例通过点击图标打开输入覆盖层，点击外部直接保存并退出。采用此模式时须确保校验失败可处理、保存状态清楚，且不会因误点丢失输入。 |
| 修改少量字段 | 就地编辑是否比跳到表单页更清楚？ | 可编辑性有提示；进入编辑后聚焦输入；提供保存、取消、校验与失败反馈。表格列宽不要因编辑而跳动。 |
| 重要与次要操作 | 主要操作应实时可见；次要操作可在对象悬停时出现。 | 不只依赖 hover；键盘焦点与触屏也可使用。点击热区可大于可视图形，但不应盖住相邻操作。 |
| 删除与二次确认 | 操作能否真实撤销？能则考虑直接执行、告知结果并提供撤销；不能则考虑靠近触发点的 Popconfirm。 | 官方 Message 示例把撤销窗口设为约 1 分钟，这是示例设定而非通用要求。撤销须覆盖后端状态与数据同步；并发、权限、超时应有明确处理。高风险或不可逆操作以业务规则为先。避免滥用 Modal 二次确认。 |
| 同一页内的多个信息组 | 内容是同一对象的平级切面，还是连续任务？ | 平级信息可用页签；相关信息用邻近与分组表达；连续任务可渐进展示，不要把所有步骤隐藏到多个无意义页面。 |
| 虚拟页面 | 是否需要在一个工作场景内组合原本分散的内容与交互？ | 把覆盖层、嵌入层与当前内容组织为连续的工作空间；这是概念性模式，不要把它误当成 antd 的具体组件。 |
| 多步骤流程 | 保持当前上下文是否真能降低成本？ | 操作选项可随用户行为或规则渐进出现；配置程序可用一组配置项引导完成任务或产品组装；合适时弹窗中也可用步骤条管理复杂流程。长流程、需要深链接/分享/历史记录或大量内容时，独立页面可能更合适。 |
